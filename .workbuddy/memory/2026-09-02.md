## 中文 Windows 写 .ps1 的两个致命坑
1. 必须 UTF-8 BOM: 中文 Windows 上默认用 GBK 读 .ps1, 无 BOM 的 UTF-8 中文会被误读, 导致字符串引号失衡、解析报"意外的标记 } / )"。修复: 用 [System.IO.File]::WriteAllText($f, $txt, [System.Text.UTF8Encoding]::new($true)) 写 BOM。Edit 工具改文件会保留 BOM, 但 Write 工具默认无 BOM。
2. Python 代码别用 python -c "$script" 传: 含双引号的多行代码经 Shell 传给外部 exe 时引号被吞 (print("torch",...) 变 print(torch,...) 报 SyntaxError)。正确做法: 把 Python 写到 .py 文件再 python xxx.py。
- 校验脚本里 fish_speech 是本地包, 需手动 sys.path.insert(0, src/fish-speech-1.5.0) 才能 import (服务由 engines/clone.py 注入); ormsgpack 是死依赖(服务未 import), 校验中已移除

## 跨硬件容量对比结论 (vs 当前 RTX 3060 12GB)
- TTS 是 launch 受限(有效带宽仅 4.5%, 每 token ~11000 次碎 kernel), 故裸升级显卡收益次线性:
  4070Ti(504GB/s) TTS ~9.5, 4080(717) ~12, 4090(1008) ~15 req/min; 3060 实测 6.2
- 真正倍增器是 CUDA Graph(消除 launch 开销, RTF 1.95→~1.0), 对 40 系 + Linux 最有效
- 显存是隐藏约束: 4070Ti 仍是 12GB → 与 3060 同样需模型调度换入换出, 并发容量无改善; 只有 4080(16G)/4090(24G) 能三模型常驻
- Apple M4 基础款(16GB 统一/120GB/s)基本不可行: 服务是 CUDA 栈(PyTorch cu124 + CTranslate2), M 系无 CUDA 且 CTranslate2 无 Metal 后端, 需移植且慢 5-10x
- 决策: 换机不改码选 4080/4090; 先不花钱则优先做 CUDA Graph; Mac 不推荐
